# 小猫搬金条 · work-time

一个手机端的工作计时 / 搬金记录小工具。纯静态页面（HTML + 原生 JS），托管在 GitHub Pages，后端用 Supabase 做账号、云同步和站内留言板。

## 计时规则（5.1）

- 实际工作、带薪摸鱼都计薪；不带薪摸鱼暂停计薪。费率 = 日工资 / 标准工时 / 3600。
- **跨午夜**：本次打卡跨了几个自然日，下班时会拆成几条记录，每天只算当天的工时与当日工资，不会把整段工时堆到上班那天。
- 计时期间系统时间回退、或超过 3 小时没运行，会进入「待核对」状态，需用户确认那段时长计入多少，不会默默算错。

## 数据怎么存的

三层：本地一份、云端两份（记录 + 进行中打卡）。

- **本地**：主页和账本页同域名，共用 localStorage，key `catGold_v5`；首次打开自动迁移 `catGold_v4 / v3 / v2`。
- **登录态**：key `mw_acct_v1`（token、refresh token、uid、昵称、过期时间）。access token 1 小时过期，到期前自动用 refresh token 续期；401 时重试一次；续期失败提示重新登录，不会静默失败。
- **云端记录**：Supabase 表 `records`，主键 `user_id + id`，RLS `own_records`（`auth.uid() = user_id`），只能读写自己的行；另建 `feedback` 表做留言板（免登录可读可发）。
- **进行中打卡**：写在当前用户的 `user_metadata.session`（不占新表），登录后每 6 秒去重推送一次；换设备登录会自动取回并继续计时（超过 3 小时的间隔会进入核对）。

## 后端配置（Supabase）

- 项目 URL 与 publishable key 写在页面里的 `SB` / `SBK` 常量（publishable 可以公开，**secret key 绝不能写进页面或仓库**）。
- Auth：邮箱提供商开启、关闭“确认邮件”（用户名登录不需要收验证邮件）、允许新用户注册。前端把用户名拼成 `用户名@xiaomao.local` 的伪邮箱，所以用户名只能用小写字母/数字/下划线，2–20 位。
- `feedback` 表只有 select / insert 两条策略，没有 delete：清理测试留言要用 Dashboard 的 SQL Editor（`delete from feedback where id = ...`）。

## 修改和上线

仓库是 GitHub Pages，`main` 分支根目录即站点。改完提交到 `main`，等 1 分钟左右自动生效。

- 改页面：直接编辑对应的 `.html` 文件
- 新增版本：复制一份改版本号，同步改 `index.html` 的跳转和账本页的返回链接
- 浏览器缓存：改了没生效，在地址后面加 `?v=2` 强刷一次

## 文件命名规范

- 主程序版本：`v主版本.次版本.修订.html`，一个版本一个文件，不覆盖旧的（`v5.0.1.html` / `v5.0.2.html` / `v5.1.html` / `v5.2.html`）
- 两个固定页面用通用名：`index.html`（站点入口）、`ledger.html`（完整账本）
- 游戏：本体 `cat-game-<版本>.html`，测试版外壳 `cat-game-beta.html`
- 附属文件：`<对应版本>-<用途>.<后缀>`，例如 `v5.0.2-short-link.zip`
- PWA：`manifest.json` + `icon.svg`，发布时自动生成
- 旧地址 `xiaomao-banjin-5.1.html` 留了一张跳转页指向 `v5.1.html`，桌面图标和旧书签不会失效；确认没人用之后可以删掉
